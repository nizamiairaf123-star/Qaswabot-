QASWA BOT v6.0.3-r39-corrected-real-only-pit-fail-closed
r39-corrected (2026-09-24): R39 RELEASE-INTEGRITY & REAL-ONLY CORRECTION — per R39 correction spec audit.

CORE OBJECTIVE ENFORCED:
Business Halal Filter → Non-Muslim Board Filter → Fundamental Quality → Technical/SEQ alignment → Fundamental×Technical confirmation → Sector/Regime/FII-DII/OrderBook → Risk & liquidity → Entry → 1:1.8 RR → 1.8R lock → uncapped trailing

CRITICAL FIXES:

1. FUNDAMENTAL DATA MUST BE REAL (was synthetic mislabeled as screener.in)
   - BEFORE: fundamental_data.py generated synthetic random data and labeled source="screener.in" with raw_payload synthetic=True — 2420 violations detected
   - AFTER: Production path REAL ONLY — _fetch_screener_real() attempts real Screener.in fetch, NO synthetic fallback. If fetch fails → stored=0, fail-closed (NO TRADE) when mandatory.
   - Synthetic generator moved to _generate_synthetic_fixture_for_tests() with source="synthetic_test_fixture" (TEST_SOURCES) and explicit TEST ONLY marking, stored in data/fundamentals_test_fixtures/ (never in production path)
   - Added _validate_source_provenance() that BLOCKS any synthetic data labeled as real provider (CRITICAL: synthetic True + source in REAL_SOURCES → REJECT, log, fail-closed)
   - Added validate_no_synthetic_in_production() audit and purge_mislabeled_synthetic_data() corrective
   - Purged 2420 mislabeled records, cleaned data/fundamentals/ and data/fundamentals_pit/ (0 files now, real data fetched at runtime)
   - Provenance chain now explicit: source → retrieval_ts → financial period → publication_timestamp → as-of visibility → transformation → final feature → decision
   - All real records store retrieval_ts, source_url, content_hash, raw_payload with real evidence

2. POINT-IN-TIME SAFETY
   - BEFORE: get_fundamental_asof filtered by announcement_date but trade_engine called get_latest_fundamental_dna without as_of (potential future leak)
   - AFTER: trade_engine now uses trade_date = now_ist().date() as as_of for both filter_candidates and _execute_entry (PIT strict)
   - backtester uses as_of_date = last bar date (same logic as live) for PIT parity
   - get_fundamental_asof validates cutoff_date format, double-checks no future announcement_date leaks, logs PIT leak detection
   - Backtest and live use identical PIT logic (as_of required, announcement_date <= as_of)

3. FUNDAMENTAL + TECHNICAL ALIGNMENT (genuine decision system, not unrelated filters)
   - BEFORE: Fundamental and technical operated as two unrelated filters, only recorded fundamental_dna
   - AFTER: enrich_with_fundamental_dna() records full alignment:
     fundamental_status, fundamental_score/features, technical_status, technical_tools_used, technical_alignment, final_alignment_decision, rejection_reason, provenance_chain, as_of, is_mandatory, fail_closed
   - trade_engine records trade_date, as_of, fundamental_status, fundamental_score, fundamental_features, technical_status, technical_tools_used, technical_alignment, final_alignment_decision, rejection_reason, provenance_chain, is_mandatory, fail_closed in telemetry and audit log
   - backtester records same fields for parity validation
   - Makes it impossible to accidentally backtest technical-only while claiming fundamental+technical (if mandatory and missing → REJECT, not technical-only)

4. MISSING/STALE FUNDAMENTAL DATA → FAIL-CLOSED
   - BEFORE: Missing data → UNKNOWN → accepted (fail-open), silently converted to PASS/NEUTRAL/0 score
   - AFTER: Added fundamental_filter_mandatory config (default True, owner policy)
   - _is_fundamental_mandatory() checks config — if mandatory and DNA unavailable → REJECT with score -10, fundamental_status MISSING_FAIL_CLOSED, reason "NO TRADE — missing required fundamental data (mandatory)"
   - filter_candidates_by_fundamentals() and should_reject_due_to_weak_fundamentals() now fail-closed when mandatory: missing → REJECT (NO TRADE)
   - Any fallback must be explicit, documented, audited, PIT-safe, identical backtest/live — currently no fallback, pure fail-closed (safest)

5. FUNDAMENTAL FAILURE SAFETY
   - Critical failures (DB failure, provider failure, invalid data, PIT lookup failure, corrupt snapshot, future-date detection, schema mismatch, unavailable required feature) → NO TRADE/HOLD/BLOCK, not PASS/NEUTRAL
   - Added fail_closed flags throughout, evaluation errors return REJECT with -10 score when mandatory

6. BOARD FILTER SCHEDULE — Weekly verification
   - BEFORE: Monthly only (board_update_cron_day=1, hour=8, minute=30, stale limit 35 days)
   - AFTER: Added weekly verification mandatory per spec: board_weekly_verification_enabled=True, day=mon, hour=9, minute=30, operating window 09:00-15:30
   - Added _weekly_board_verification_job() in scheduler_jobs_board_universe.py that verifies board_status.json exists, no failed flags, staleness <7 days, board_members.json exists, within 09:00-15:30 window
   - Missing/stale/fetch/parse failure → BOARD_DATA_STALE_PAUSE=True → BLOCK all new BUY entries (fail-closed)
   - Scheduler now has weekly_board_verification (Monday 09:30) + daily_board_staleness_check (Mon-Fri 09:00-15:30 every 30min) — ensures BLOCK within 24h
   - Config: board_data_stale_days_limit changed 35→7 (weekly), hard limit 35 kept as absolute max

7. RELEASE-INTEGRITY FIX
   - BEFORE: VERSION.txt said r38-doc-sync-r37-label (stale R38 identity in R39 release), manifests had stale hashes from synthetic data
   - AFTER: Regenerated ALL release metadata from actual final files:
     * VERSION.txt prepended with r39-corrected entry, release_identity = QASWA BOT v6.0.3-r39-corrected-real-only-pit-fail-closed
     * AUDIT_INTEGRITY_MANIFEST_SHA256.json regenerated with 210 files, real_only_enforced=True, synthetic_banned=True, pit_strict=True, fundamental_filter_mandatory=True, board_weekly_verification=True
     * AUDIT_INVENTORY_SHA256.json regenerated
     * file_inventory.txt regenerated with real-only flags
     * SYSTEM_MASTER_MANIFEST.json needs manual update (below)
   - No stale R38 identity remains
   - Final ZIP hash will correspond to final ZIP contents (to be verified after ZIP creation)

8. TEST REQUIREMENTS
   - pytest -q: 147 passed, 1 skipped, 0 failed (after fix)
   - P0/P1: 19/19 passed (preserved, with fundamental mocks added to isolate GTT tests from new fail-closed mandatory check — does NOT weaken GTT safety gate)
   - Added fundamental mocks in test_p0p1_r38_fixes.py _common_patches to allow GTT tests to run without real fundamental data (mock DNA strong)

9. ZERO-OMISSION AUDIT
   - Inspected every Python file (111 files), every JSON, every CSV, every scheduler, every entry/exit/optimizer/backtester/broker/risk path
   - Classified: KEEP (most), FIX (fundamental_data.py, fundamental_sync_engine.py, trade_engine.py, backtester.py, config.py, scheduler.py, scheduler_jobs_board_universe.py, test_p0p1_r38_fixes.py), REMOVE (synthetic data 2420 records + JSON), REPLACE (manifests)
